# 要件定義書

## 1. 目的

ユーザーがログイン後に短文投稿を行い、投稿一覧を検索・ページングしながら閲覧できるマイクロブログサービスを提供する。

## 2. 対象範囲

- 対象システム: Webフロントエンド + APIバックエンド + PostgreSQL
- 本書の対象: 現行実装ベースの機能・運用要件

## 3. 想定ユーザー

- 一般利用者
  - アカウント登録
  - ログイン/ログアウト
  - 投稿作成/削除
  - 投稿一覧閲覧（検索・ページ移動）
  - ユーザー名/アイコン更新

## 4. 機能要件

### 4-1. ユーザー登録

- ユーザーは新規登録できること
- 入力項目
  - ユーザー名
  - メールアドレス
  - パスワード
- 入力制約
  - メール形式
  - パスワード6文字以上
- 重複制約
  - ユーザー名重複不可
  - メールアドレス重複不可

### 4-2. ログイン/認証維持

- ユーザー名とパスワードでログインできること
- ログイン成功時に access token を取得できること
- refresh token は Cookie で管理されること
- access token 期限切れ時に refresh で再発行できること

### 4-3. ユーザー情報取得/更新

- ログイン済ユーザーは自分の情報を取得できること
- ユーザー名を更新できること
- アイコン画像を更新できること

### 4-4. 投稿作成/削除

- ログイン済ユーザーは投稿を作成できること
- 投稿本文は1〜140文字であること
- 自分の投稿のみ削除できること

### 4-5. 投稿一覧表示

- ログイン済ユーザーは投稿一覧を取得できること
- 一覧は新しい投稿順で表示されること
- 以下で絞り込み可能であること
  - 投稿本文（word）
  - 投稿者名（user_name）
- `page` によるページ移動ができること

### 4-6. ログアウト

- ログアウト操作でサーバー側認証状態を破棄できること
- ログアウト後はサインイン画面へ遷移すること

## 5. 画面要件

### 5-1. サインイン/サインアップ画面 (`/`)

- ログインフォームと新規登録フォームを表示すること
- エラー時にメッセージとトーストで通知すること

### 5-2. メイン画面 (`/main`)

- ヘッダー、投稿入力エリア、投稿一覧エリアを表示すること
- 認証未完了中は `authLoading` により遷移判定を保留すること
- 未ログイン時はサインイン画面へ遷移すること

## 6. API要件

- API仕様は `docs/04_api_spec.md` に準拠すること
- 認証が必要なエンドポイントは JWT を検証すること

## 7. データ要件

- DBスキーマは `docs/03_db_schema.md` に準拠すること
- 最低限、以下テーブルを持つこと
  - `user`
  - `auth`
  - `micro_post`

## 8. 非機能要件

### 8-1. 利用環境

- モダンブラウザで利用可能であること

### 8-2. セキュリティ

- パスワードはハッシュ化保存すること
- 認証が必要な API は JWT を検証すること
- refresh token は httpOnly Cookie で扱うこと

### 8-3. 保守性

- フロント/バックを分離した構成であること
- 静的解析・テスト可能な構成であること
- クライアント側データ取得は TanStack Query を基本とすること
